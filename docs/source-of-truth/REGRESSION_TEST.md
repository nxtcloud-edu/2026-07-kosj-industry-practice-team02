# 회귀 테스트 - 실패 질문의 KB 개선 전후

## 목적

우리 팀의 핵심 차별점인 `실패 질문 → KB 후보 → 담당자 승인 → 동일 질문 재질의 개선`이 실제 데이터 상태 변화로 작동하는지 검증한다.

## 테스트 ID

`REG-01-BED-FRAME-FEE`

## 준비 상태

- 질문: `침대 2인용 프레임 수수료가 얼마예요?`
- 공식 출처: 세종특별자치시시설관리공단 대형폐기물 배출항목선택
- 공식 값: 2인용 침대 프레임 10,000원
- `KB-WASTE-03`은 출처대장에 존재하지만 초기 `kb_documents`의 ACTIVE 검색 대상에서는 제외한다.

## 단계와 기대 결과

| 단계 | 행위 | 기대 결과 |
|---:|---|---|
| 1 | 시민이 질문 입력 | `대형폐기물`로 분류 |
| 2 | ACTIVE KB 검색 | 세부 수수료 근거 없음 |
| 3 | 시민 응답 | `INSUFFICIENT_GROUNDING` 폴백, 임의 금액 생성 금지 |
| 4 | 이벤트 저장 | 성공/폴백 메타데이터 저장, PII가 없으므로 masked_question 저장 |
| 5 | 운영자 검토 | 사유 확인, 후보 적격 `true` |
| 6 | KB 후보 작성 | 제목·대표 질문·답변·수수료·기관·공식 출처·확인일 입력 |
| 7 | 승인 요청 | 상태 `PENDING_APPROVAL` |
| 8 | 작성자 본인 승인 시도 | API가 거부 |
| 9 | KB 승인자 승인 | 상태 `APPROVED`, ACTIVE KB 생성 |
| 10 | 동일 질문 재질의 | `SUCCESS`, 10,000원과 공식 출처 카드 제공 |

## 성공 기준

- 승인 전에는 금액을 생성하지 않는다.
- 승인되지 않은 후보가 검색 결과에 나타나지 않는다.
- 작성자 본인 승인이 차단된다.
- 승인 후 동일 질문의 결과가 실제로 달라진다.
- 출처명·URL·확인일은 서버가 KB 메타데이터에서 결합한다.
- 감사 이력에는 상태·행위·대상 ID만 남고 질문 전체 스냅샷은 남지 않는다.
