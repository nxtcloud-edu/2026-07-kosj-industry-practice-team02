# 인간이 알아야 할 것과 AI가 자율 처리할 것

## 인간에게 반드시 설명·승인 요청

| 영역 | 예시 | 이유 |
|---|---|---|
| 제품 범위 | P2를 MVP로 이동, 지원 민원 추가 | 일정·데이터·UI·평가 영향 |
| 사용자 동작 | 폴백 문구, 기관 연결, 승인 절차 | 신뢰와 책임 |
| 개인정보 | 마스킹 범위, 보관기간, 로그 | 법적·평판 위험 |
| 공식 데이터 | 출처 선정, 수수료/기간 값 | 행정 정확성 |
| 공급자 | LLM, DB, 배포, 지도 | 비용·보관·종속성 |
| 공개 계약 | API breaking change | FE/BE/테스트 영향 |
| DB | 스키마 파괴, 데이터 삭제, migration | 복구 위험 |
| 권한 | admin 보호, 역할, 자기 승인 | 무단 배포 위험 |
| 의존성 | 새 production package | 보안·유지비 |
| 배포 | 도메인, CORS, secret, public URL | 운영 위험 |
| KPI | 성공률 정의와 공개 수치 | 평가 신뢰성 |
| Source control·접근 | repository visibility/owner, collaborator, GitHub App scope, merge 권한 | 소스·비밀·감사·공급망 위험 |
| Cloud 경계 | Cloud secret, internet, 자동 병합, local-only 검증 대체 | 외부 전송·잘못된 완료 주장 위험 |

## AI가 자율 처리 가능

- 같은 공개 계약 안의 내부 함수 구조
- 테스트 픽스처와 helper
- 포맷팅·린트·타입 오류
- 작은 비공개 리팩터링
- 중복 제거와 명명 개선
- 문서 링크·색인·오탈자
- 성능에 영향 없는 파일 배치

자동화 범위에는 branch 작성, PR 준비와 검증 증거 정리가 포함될 수 있지만 merge, repository
visibility 변경, collaborator/App 권한 부여, secret 등록, 공개 배포는 포함되지 않는다.

## 경계가 애매할 때

다음 중 하나라도 해당하면 인간 질문으로 승격한다.

- 사용자에게 보이는 행동이 달라짐
- 데이터 저장/삭제/전송이 달라짐
- 외부 비용·쿼터가 달라짐
- 롤백이 어렵거나 파괴적임
- 여러 앱/팀의 계약이 달라짐
- 정답 데이터나 평가 지표가 달라짐
- GitHub/Cloud actor가 접근·merge·secret·internet 권한을 새로 얻음

- ...
