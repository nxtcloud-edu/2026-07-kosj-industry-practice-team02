## 5. 설계안과 버린 대안

### 추천안 A

DB function/trigger/check가 승인·상태·파기를 원자적으로 강제하고 RLS/GRANT가 직접 접근을 차단한다. backend service도 같은 정책을 중복 검증해 안전한 사용자 오류를 만든다. migration은 타입·table, invariant/function, permission/RLS, index/view의 계층으로 분리하고 위험 변경마다 별도 보상 SQL과 pgTAP/catalog test를 둔다.

### 대안 B

backend transaction을 중심으로 두고 DB는 기본 FK/check/권한만 사용한다. 초기 구현은 작지만 직접 SQL·다른 writer·동시성 경로가 정책을 우회할 가능성이 더 크다.

### 보류한 대안

전체 정규화는 현재 공개 draft와 MVP 일정에 비해 변경 폭이 크다. 실제 증거가 생기기 전에는 8-table 형태를 유지한다. 전역/unpinned CLI와 매번 latest 사용도 재현성이 없어 제외한다.
