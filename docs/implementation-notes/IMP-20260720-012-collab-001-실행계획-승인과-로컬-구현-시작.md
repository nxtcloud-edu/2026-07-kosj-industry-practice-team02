## 5. 설계 결정과 대안

### 선택

승인 문서를 먼저 검증·로컬 commit으로 고정한 뒤 ignored `.worktrees/` 아래 격리 branch에서 세
독립 TDD unit을 병렬 구현한다. 각 unit은 별도 implementer와 reviewer를 거치고 통합 branch에서
workflow/static tests와 전체 feasible gate를 다시 실행한다.

### 이유

현재 dirty 문서와 구현 변경을 섞지 않고 첫 remote commit의 계보를 명확히 하며, history scanner와
untrusted PR scope 처리처럼 보안 민감한 코드를 독립 검토하기 위해서다.

### 고려했지만 선택하지 않은 대안

- dirty `main`에서 병렬 직접 편집: 문서 승인 기준점과 구현 diff가 섞여 리뷰/rollback이 약해진다.
- account identifier 추정 또는 임의 remote 생성: 잘못된 owner/visibility로 외부 상태를 바꾸므로 금지한다.
- GitHub secret에 DeepSeek/DB 값을 넣어 full actual gate 실행: 승인 경계를 위반하므로 제외한다.
