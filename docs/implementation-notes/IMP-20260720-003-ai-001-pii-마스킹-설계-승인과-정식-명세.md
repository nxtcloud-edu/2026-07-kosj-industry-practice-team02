## 5. 설계 결정과 대안

### 선택

- Python 표준 라이브러리만 사용하는 import-safe 순수 함수
- 13개 닫힌 `PiiCategory`와 5개 닫힌 `UnresolvedReason`
- 원문 값/hash가 없는 불변 finding과 고정 한국어 치환 token
- NFKC·zero-width 재검사·위험 bidi/control 거부
- 13개 범주의 명시적 total priority order와 그 안의 긴 span→앞선 span 겹침 해소
- 잔여 위험 재검사 후 불확실하면 `masked_text=None`, 양 안전 플래그 false
- 미해결 시 metadata-only event만 허용하고 실패 질문 text/row·provider 호출 금지
- `apps/api/tests/privacy/fixtures/pii_masking_cases.v1.json`의 최소 case 구성과 동결·완화 gate

### 이유

새 production dependency와 외부 model 없이 offline·재현 가능하게 검증할 수 있고, 판단이
불확실한 입력을 억지로 통과시키지 않아 원문 미저장 원칙을 지킨다. 닫힌 타입과 값 없는
finding은 downstream이 문자열을 자의적으로 해석하거나 탐지 값을 다시 노출할 위험을 줄인다.

### 고려했지만 선택하지 않은 대안

- 외부 NER/PII library: 새 production dependency·모델 provenance·offline 재현 비용이 생긴다.
- LLM 기반 마스킹: 원문을 마스킹 전에 외부 전송하는 순환 위험과 비결정성이 있다.
- 탐지 부분 성공값 저장: 잔여 개인정보를 장기 보관할 수 있어 비협상 정책과 충돌한다.
