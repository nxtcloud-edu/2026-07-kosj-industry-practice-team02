## 5. 설계 결정과 대안

### 선택

- 현재 폴더를 원격 없는 독립 `main` 저장소로 초기화하고 기준선 커밋 뒤 `.worktrees/` 아래 `codex/` 작업 브랜치를 만든다.
- 구현은 `superpowers:subagent-driven-development` 흐름으로 한 작업씩 구현자→독립 검토자→필요 시 수정/재검토한다.
- 모든 기능은 TDD의 실패 테스트→최소 구현→통과 확인 순서를 적용한다.
- 중요한 아키텍처 판단, 설치/변경 명령, 최종 diff·보안·완료 판정은 `/root`가 직접 수행한다.

### 이유

- 기존 사용자 파일을 기준선으로 보존하면서 각 수직 흐름을 독립 검토·롤백할 수 있다.
- 병렬 코딩으로 shared state 충돌을 만들지 않고, 구현과 검토의 문맥 독립성을 확보한다.
- 원격·CI가 없는 local-first 결정에서도 재현 가능한 명령 증거를 남길 수 있다.

### 고려했지만 선택하지 않은 대안

- 현재 폴더에서 바로 코딩: 기준선과 구현 diff가 섞여 롤백·검토가 어려워 제외했다.
- 여러 구현 에이전트의 동시 쓰기: 동일 manifest/lock/계약 충돌 위험 때문에 제외했다.
- 공개 저장소·호스팅을 동시에 구성: 사용자 승인 범위 밖이므로 보류했다.
- 부모 Git 저장소 재사용: 다른 프로젝트의 이력을 오염시킬 위험이 있어 사용하지 않았다.
