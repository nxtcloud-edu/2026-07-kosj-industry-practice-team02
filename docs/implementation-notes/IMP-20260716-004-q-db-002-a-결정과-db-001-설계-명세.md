## 5. 설계 결정과 대안

### 선택

`app_private`의 8개 base table과 `app_api`의 제한 view/function을 사용한다. `PUBLIC`/browser role/base backend role의 직접 table DML은 차단한다. 승인·event/failure·purge는 reviewed SECURITY DEFINER function에서 원자적으로 처리하며 backend가 같은 규칙을 선검증한다.

### 이유

공공 민원 MVP의 핵심 실패는 단순 application bug가 아니라 미승인 지식 노출, 자기 승인, 텍스트 미파기, mock 공식 오인이다. 이 규칙은 데이터가 존재하는 최종 경계와 사용자 오류를 다루는 application 경계 양쪽에서 검증해야 한다.

### 고려했지만 선택하지 않은 대안

- backend 중심 최소 DB: direct writer와 concurrency 우회에 약해 Q-DB-002에서 거절.
- 전체 정규화: current MVP와 공개 draft에 비해 변경 폭이 커서 보류.
- public table + permissive RLS: exposed schema 오설정 위험을 줄이지 못해 제외.
- global/latest CLI와 npm lifecycle install: exact 재현·checksum 경계가 없어 제외.
