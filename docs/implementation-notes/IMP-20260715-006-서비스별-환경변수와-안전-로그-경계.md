### Acceptance Criteria

- root 환경 예시는 변수 할당 없이 Web/API 템플릿 위치만 안내한다.
- Web 예시는 승인된 공개 변수 한 개만 포함하고 서버 비밀 이름은 포함하지 않는다. API 예시는 민감값을 비우고 provider를 기본 비활성화하며 승인된 제한값을 고정한다.
- HTTP 로그는 서버 생성 UUID `request_id`, method, 라우트 템플릿 path, status 네 필드만 기록한다. body·query·raw path·header·cookie·인증값·client 주소·답변·provider/DB 상세는 기록하지 않는다.
- 정상·일반 예외·미매칭·허용되지 않은 method에서 요청당 안전한 메타데이터 한 줄만 남고, 예외는 500 기록 후 다시 전달한다. Uvicorn access/ASGI trace, request-derived exception 상세와 client/path/query 인자를 담는 고정 WebSocket INFO record가 출력되지 않으며 공식 launcher는 `--ws none`을 사용한다.
- 저장소 비밀 패턴 검사와 브라우저 전송 산출물 검사는 clean `0`, 탐지 `1`, 운영 오류 `2+`를 반환하며 값이나 파일 내용을 출력하지 않는다.
- 기존 health/readiness 계약, 의존성·lock, 공개 API, DB·데이터·프롬프트는 바꾸지 않는다.

## 5. 설계 결정과 대안

### 선택

- root는 안내만 두고 Web/API 환경 예시를 분리했다. Web은 공개 allowlist 한 개, API는 빈 민감값과 disabled provider 기본값만 둔다. 성공/범위 밖 질문 텍스트 미저장은 끌 수 있는 환경 toggle로 만들지 않았다.
- `receive`를 읽지 않는 pure ASGI middleware가 response start의 status와 route template만 관찰한다. 로그 formatter는 message·args·traceback을 직렬화하지 않고 네 필드만 출력한다.
- 미매칭 raw path는 고정 `<unmatched>`로 치환한다. request ID는 client 입력을 받지 않고 서버에서 UUID를 생성한다.
- Uvicorn access·ASGI raw trace는 disabled/non-propagating으로 고정한다. error logger는 startup/일반 error를 살리되 INFO 미만 protocol detail과 exact pinned WebSocket INFO template을 버리고 exception record를 generic message로 정규화한다. 공식 launcher도 `--no-access-log --ws none`을 사용한다.
- secret scanner는 Git active-file 목록과 stable rule ID를 사용하며 일반/`export`, PowerShell `$env:`, cmd `set ` 형식의 승인된 secret assignment를 검사한다. bundle scanner는 build-time materialized `.next/static`, app HTML/RSC, pages HTML을 byte 단위로 검사한다. 둘 다 값 대신 path/rule/count만 출력한다.

### 이유

allowlist와 관찰하지 않는 데이터 흐름을 함께 사용해야 formatter 실수, raw URL, access/trace/Upgrade logger 같은 우회 유출 경로를 줄일 수 있다. browser scanner를 build-time materialized artifact에 한정하면 server-only chunk의 의도된 설정 이름 때문에 생기는 거짓 양성을 피하면서 현재 정적 산출물 경계를 검증할 수 있다. 동적 응답 검사는 후속 live-response gate가 맡는다.

### 고려했지만 선택하지 않은 대안

- `BaseHTTPMiddleware` 또는 body를 읽고 다시 주입하는 middleware: 원문을 불필요하게 관찰하고 streaming/body 보존 위험이 있어 제외했다.
- raw path, query, client 제공 request ID, 예외 메시지를 기록: 시민 입력·식별정보가 섞일 수 있어 제외했다.
- 모든 Uvicorn error를 끄기: startup과 운영 오류까지 잃으므로 선택하지 않고 레벨/exception 단위 filter를 사용했다.
- 전체 `.next/server` JavaScript 검사: 브라우저에 전송되지 않는 server-only chunk의 거짓 양성을 만들어 제외했다.
- 엔트로피 기반 전수 비밀 판정: 안정적이지 않은 오탐과 값 노출 위험 때문에 승인된 pattern/marker gate로 한정했다.
- 질문 텍스트 저장 정책을 env toggle로 제공: 비협상 개인정보 불변조건을 운영자가 끌 수 있어 제외했다.

### 데이터 흐름/상태 변화

1. HTTP ASGI scope가 middleware를 지나지만 request receive channel, body, query, header, cookie, client 정보는 읽지 않는다.
2. downstream 응답의 status만 관찰하고 종료 시 route template을 조회해 네 필드 JSON 한 줄을 기록한다. 일반 예외는 500 metadata를 기록한 뒤 원래 예외를 다시 전달한다.
3. Uvicorn request-line/ASGI trace와 pinned WebSocket INFO 경로는 차단되고 error exception record는 generic 값으로 정리된다. 현재 범위 밖 WebSocket은 공식 launcher에서도 비활성화된다.
4. 저장소 scanner는 Git active files의 지원되는 정적 assignment를 읽어 rule별 개수만 보고한다. bundle scanner는 build-time materialized browser artifact의 승인된 marker만 읽는다.
5. 시민 질문, 공식 KB, mock, DB, provider payload의 상태 변화는 없다.

### 오류·빈 상태·롤백

- scanner clean은 무출력 exit `0`, 탐지는 path/rule/count만 출력하고 `1`, 입력 누락·파일 읽기·Git discovery 같은 운영 오류는 `2+`다.
- browser artifact가 없거나 검사 가능한 browser 파일이 없으면 clean으로 오인하지 않고 운영 오류로 끝난다.
- app 예외는 공개 500 body에 exception text를 넣지 않고 safe metadata를 남긴 뒤 기존 예외 처리를 보존한다.
- task commit 전에는 지정 파일 단위 restore/remove로 되돌리고, commit 후에는 기록된 task commit을 `git revert`한다. DB/data recovery는 변경이 없어 필요 없다.

## 9. 보안·개인정보·접근성·성능 영향

- Privacy: middleware가 request body/query/header/cookie/client/raw path를 읽지 않고, 질문 원문·응답·masked question을 일반 로그에 남기지 않는다. 저장·보관·삭제 정책과 DB row는 바뀌지 않았다.
- Security: browser/server env를 분리하고, Uvicorn 우회 로그와 exception 상세를 차단했으며, 저장소/브라우저 artifact scanner를 추가했다. 단, Git history·process env·외부 수집기·인코딩/분할된 비밀은 검사 범위 밖이다.
- Accessibility: 사용자 UI와 DOM/CSS 변경이 없어 영향 없음. Web shell의 기존 390/430px·키보드·대비 검증은 유지된다.
- Performance/cost: 요청당 작은 JSON 한 줄과 UUID 생성 비용만 추가된다. body buffering·provider/DB I/O·새 dependency·외부 비용은 0이다. 100-user 성능은 `PERF-001`에서 측정한다.

## 10. 데이터와 출처 영향

- 공식 데이터: 추가·변환·승인·ACTIVE 전환 0건. source URL/확인일 변경 없음.
- mock/AI 생성: 저장 데이터 0건. 테스트에서만 합성 sentinel과 임시 artifact를 만들고 종료 시 삭제했다. 실제 개인정보·실제 secret은 사용하지 않았다.
- schema/lineage: DB schema, migration, 계약 schema, data manifest 변경 없음. 로그는 persistence schema가 아니라 transport metadata 출력 경계다.
- verified date: 2026-07-15 KST. 검증 대상은 저장소 코드/문서와 로컬 합성 실행 결과이며, 외부 공식 행정 데이터 검증은 해당하지 않는다.

## 11. 인간이 반드시 알아야 하거나 승인할 내용

- Web 환경에는 승인된 공개 설정만 둘 수 있고, DB/provider/context secret은 API runtime에만 주입해야 한다. 실제 값을 예제·Git·브라우저 번들에 넣지 않는다.
- 공식 API 실행은 access log를 끄는 옵션을 유지해야 한다. 공개 배포 시 reverse proxy와 hosting provider 자체 access/error log는 별도 인간 검토가 필요하다.
- scanner clean은 “알려진 literal/pattern이 현재 active 파일과 browser artifact에 없다”는 뜻이지, 저장소 history·외부 log·process env·인코딩된 secret까지 안전하다는 보증이 아니다.
- 개인정보 원문 미저장과 `OUT_OF_SCOPE` 텍스트 미저장은 환경변수로 완화할 수 없는 정책이다. 보관·로그 필드·외부 공급자·공개 배포 변경은 다시 승인받아야 한다.
- 새 production dependency, 공개 API, DB migration/삭제, 실제 공식 데이터, 실제 시민 provider 사용은 이번 변경에 포함되지 않았다.

## 12. AI 내부 구현 세부 — 필요할 때만 보면 되는 내용

- formatter는 log message와 exception formatting 경로를 호출하지 않고 UUID/method/path/status를 각각 안전한 기본값으로 정규화한다.
- logger 구성은 반복 호출해도 safe handler/filter가 하나만 남도록 idempotent하게 만들었다.
- route object가 없거나 잘못된 값이면 `<unmatched>`, method/status가 허용 범위를 벗어나면 안전한 기본값을 사용한다.
- secret scanner는 Windows PowerShell 5.1, UTF-8 BOM/한글/공백 경로, 다중 explicit path, stable sorted output을 테스트한다. symlink는 의도적으로 따라가지 않는다.
- bundle scanner는 파일을 byte buffer로 읽고 browser-transmitted scope만 재귀 탐색한다. server-only JavaScript와 cache는 제외한다.

## 14. 남은 위험·미해결 질문·다음 단계

- hosting/reverse proxy/인프라 logger는 이번 local app filter의 통제 밖이다. 공개 배포 승인 때 별도 access/error log와 retention 검증이 필요하다.
- pattern scanner는 history·runtime environment·cloud secret store·난독화/인코딩/분할 값을 찾지 않는다. 배포 전 provider-side secret scan과 수동 검토가 남는다.
- 정적 assignment 검사는 `set NAME=value`와 PowerShell `$env:NAME=value`까지만 보장하며 `setx`, `Set-Item Env:`, process API는 별도 runtime 검토가 필요하다.
- bundle scanner는 build-time materialized HTML/RSC/static만 다룬다. 동적 live HTML/RSC와 Pages Router `_next/data` 응답은 DEV-001D live-response sentinel gate에서 확인한다.
- 일반 `Exception` 밖의 cancellation/process interruption에서는 요청당 로그 한 줄을 보장하지 않는다. 운영 요구가 생기면 종료 semantics를 별도 설계한다.
- symlink 테스트는 Windows 권한이 없으면 skip된다. 실제 정책은 symlink를 따라가지 않는 것이며 권한 있는 CI/개발기에서 재확인할 수 있다.
- 기존 Starlette TestClient가 httpx의 deprecated `content=` 사용 경고 1건을 낸다. 기능 실패는 아니며 dependency 변경 승인 없이 이 Task에서 수정하지 않았다.
- DEV-002A task commit과 fresh 전체 diff review는 `/root`가 문서 diff 검증 후 마감한다. Phase 1은 아직 In Progress다.
