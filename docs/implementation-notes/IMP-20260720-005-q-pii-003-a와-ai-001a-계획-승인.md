## 5. 설계 결정과 대안

### 선택

모든 phone-shaped input value를 `[전화번호]`로 마스킹한다. 번호 없는 “대표전화는 어디서
확인하나요?” 문구는 SAFE negative로 허용하지만 실제 번호가 있으면 label과 무관하게 가린다.

### 이유

입력 label은 공식 데이터 provenance가 아니며 신뢰하면 개인 번호를 보존하는 우회가 생긴다.
현 one-argument pure core, local-first 0원, 공식 데이터 계보 분리도 그대로 유지된다.

### 고려했지만 선택하지 않은 대안

승인된 공식번호 집합을 core에 주입해 exact match를 보존하는 B는 signature, data version/lineage,
cache와 stale-data readiness 재설계가 필요하고 현 슬라이스 범위를 넘어 선택하지 않았다.
