## 5. 설계 결정과 대안

### 선택

- PR #4 병합을 잠시 보류한다.
- owner lane의 노트 012/013/015를 먼저 `main`에 반영한다.
- 협업자 브랜치를 최신 `main`에 맞춘 뒤 협업자 노트의 파일명·제목·INDEX 식별자를 예약된 `IMP-20260721-014`로 함께 변경한다.

### 이유

- 동일 ID를 가진 서로 다른 노트를 허용하지 않고, 문서 계보를 보존하면서 일반적인 Git 병합 충돌도 예방한다.

### 고려했지만 선택하지 않은 대안

- PR #4를 지금 바로 병합: 현재 GitHub에서는 가능하지만 owner 노트를 나중에 반영할 때 중복 ID와 INDEX 충돌이 발생한다.
- owner 노트를 재번호화: 이미 owner 문서 012/013/015와 후속 기록이 연결되어 있어 변경 범위가 더 크다.
- 두 노트 모두 012 유지: 식별자 유일성을 깨뜨리므로 허용하지 않는다.
