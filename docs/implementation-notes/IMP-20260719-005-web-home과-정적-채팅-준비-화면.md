## 5. 설계 결정과 대안

### 선택

- `/chat`은 React client directive가 없는 정적 Server Component로 구현했다.
- 홈 진입은 JavaScript router가 아닌 native `<a href="/chat">`로 구현했다.
- Playwright는 `apps/web` importer가 아니라 자체 workspace/lock을 가진 `tools/web-e2e`에 둔다.
- root verification이 standalone frozen install과 실제 prod list/deploy boundary를 영구 실행한다.
- 브라우저 네트워크는 same-origin만으로 끝내지 않고 필요한 exact path만 허용한다.

### 이유

사용자에게 보이는 다음 흐름을 만들면서도 질문 수집이나 공식 답변을 가장 작은 변경으로 피할 수
있다. 별도 E2E importer는 Next의 optional `@playwright/test` peer가 Web production graph에
결합되는 pnpm 동작을 구조적으로 차단한다. 실제 list와 deploy를 함께 검사해 선언만 dev-only인
상태와 운영 산출물까지 dev-only인 상태를 구분한다.

### 고려했지만 선택하지 않은 대안

- `/chat`을 계속 404로 둠: 승인된 대표 사용자 흐름이 끊기므로 제외했다.
- 입력창만 먼저 표시: 수집·저장·오류·개인정보 기대를 만들고 API/ACTIVE KB가 없어 제외했다.
- Playwright를 `apps/web` devDependency로 유지: pnpm이 Next optional peer로 production deploy에
  Playwright 약 17.6MB를 포함해 독립 리뷰에서 Important로 반려됐다.
- 같은 root workspace의 sibling package만 사용: peer 해석에서 완전 격리를 증명하지 못해 제외했다.
- same-origin/non-`/api` 요청만 허용: `/track` 같은 분석 요청을 놓쳐 제외했다.
- CSS `zoom=2`만 사용: 실제 브라우저 UI zoom이 아니므로 보조 증거로만 남기고 OS-level shortcut
  기반 headed Chromium 200%를 별도 검증했다.

  DeepSeek attempt는 0이다. Playwright는 production deploy에서 제거되고 local test에만 있다.
