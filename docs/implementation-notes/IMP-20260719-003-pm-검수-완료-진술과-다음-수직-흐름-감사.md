## 5. 설계 결정과 대안

### 선택

- 사용자 발화는 D-034의 검수 완료 **진술 접수**로만 기록했다.
- canonical evidence를 채울 명시적 결정 전에는 DATA-001을 Approved로 바꾸지 않는다.
- DATA-SEED 추천은 기존 schema를 유지하는 immutable filesystem release + deterministic
  transactional seed로 제한했다. compensation은 참조 row가 없는 초기 빈 disposable local DB만
  허용하고 나머지는 fail closed/new release로 교정한다.
- WEB-HOME은 404 링크를 만들지 않고 `/chat` destination 결정을 KEEP한다.

### 이유

작성자가 자기 후보를 승인할 수 없고, 시민 검색은 ACTIVE+OFFICIAL KB만 사용해야 한다. reviewer와
레코드 disposition을 AI가 만들어내면 이 두 경계가 감사상 무의미해진다. 새 DB ledger는 local-first
데모에 필요하지 않고 migration/security 범위를 불필요하게 키운다.

### 고려했지만 선택하지 않은 대안

- AI 권고안을 즉시 PM 승인으로 복사: 사람 결정을 위조하므로 제외.
- approval manifest 없이 release 생성: ADR-0015와 승인 정책 위반으로 제외.
- 새 DB release ledger: 추후 운영 확장 후보지만 현재는 새 migration 승인과 비용 대비 가치가 낮음.
- `/chat` 404 링크: 사용자 오류를 의도적으로 만들므로 제외.
