## 5. 설계 결정과 대안

### 선택

- one-argument pure function `redact_question(str)`와 closed enum/frozen slotted dataclass.
- 표준 라이브러리의 bounded precompiled regex, value-only half-open offsets와 fixed token.
- category priority→긴 span→이른 위치 선택, text order finding과 reverse replacement.
- unsafe Unicode·독립 이름/상세주소 모호성·미분류 high-risk residual은 `masked_text=None`.
- 실제 번호가 없는 대표전화 문의 문구만 safe negative; 실제 phone-shaped value는 label 무관 mask.

### 이유

재현 가능한 보안 경계, 원문 무보관, 0원 local-first와 공식 데이터 provenance 분리를 동시에
지킨다. 마스킹 성공 flag는 저장/provider 허가가 아니라 상위 정책의 필요조건일 뿐이다.

### 고려했지만 선택하지 않은 대안

- 외부 NER/PII dependency: 비용·공급망·결정성 증가로 승인 범위 밖이다.
- 공식번호 allowlist 주입: signature/data version/cache/readiness 재설계가 필요해 Q-PII-003 B로 기각됐다.
- 모호 이름·주소 fail-open: Q-PRIV-002=A 재현율 우선 정책과 충돌해 선택하지 않았다.
- fixture를 구현에 맞춰 완화: 보안 계약 약화이므로 금지했다.
