## 5. 설계 결정과 대안

### 선택

1. DeepSeek는 정확한 `deepseek-v4-flash`, thinking disabled, JSON object, `max_tokens=1024`를 사용한다.
2. 실제 outbound attempt는 재시도·timeout·429·invalid output을 포함해 process run당 30회이며 네트워크 전 원자 예약한다. 동시성 1, app retry 최대 1, client hidden retry 0이다.
3. `DEEPSEEK_ENABLED=false`가 기본이고 local/private server-allowlisted synthetic evaluation mode에서만 실제 호출한다. cap/장애는 우선 template/정책 200으로 degrade한다.
4. 화면 transcript와 token은 current-tab memory에만 두고 서버/브라우저 persistent storage/analytics/log에 저장하지 않는다.
5. 15분 HMAC-SHA-256 token에는 version, intent/region/status enum, server-defined follow-up option ID, `iat`/`exp`만 허용한다. token은 인증·공식 사실·ACTIVE 판단이 아니다.
6. 만료/위변조/미지원 token은 401/403/500이 아니라 문맥 없는 새 요청으로 처리하고 FALLBACK response token은 항상 null이다.
7. `session_id` 제거와 response required field 추가를 API 2.0.0-draft breaking change로 기록하되, 구현/외부 소비자가 없으므로 route `/api/v1/chat`은 유지한다.

### 이유

- 합성 전용과 app cap은 사용자의 기존 잔액·0원 예산·비실사용 의도를 동시에 지킨다.
- provider 장애가 곧 서비스 장애는 아니다. ACTIVE KB template이 안전하면 시민에게 200 근거 응답을 유지할 수 있다.
- current-tab context는 챗봇 연속성을 주면서 raw transcript 서버 보관·삭제·session cleanup을 만들지 않는다.
- HMAC은 payload 비밀성을 제공하지 않으므로 최소 closed claim과 서버의 매 요청 재검증이 필요하다.

### 고려했지만 선택하지 않은 대안

- `deepseek-v4-pro`: 품질 여지는 있으나 사용자가 Flash A를 선택했고 비용·지연·잔액 보호에 불리해 제외.
- thinking enabled: 기본값에 맡기면 비용/지연과 reasoning 노출 경계가 커져 제외.
- 서버 TTL session/transcript DB: UX 연속성은 좋지만 보관·삭제·인증·확장 복잡도가 불필요해 제외.
- JWT/session production package: HMAC 표준 라이브러리로 충분하고 새 dependency·오용 위험이 있어 제외.
- token에 질문 요약/출처/KB 사실 저장: 암호화되지 않고 stale fact/PII가 섞일 수 있어 금지.
- 모든 provider cap/오류를 503: deterministic safe fallback이 가능한 경우까지 장애로 만들어 제외.

### 데이터 흐름/상태 변화

```text
current-tab question + optional opaque context token
→ token signature/TTL/closed-claim validation (invalid => no context)
→ conservative PII mask
→ policy + ACTIVE KB retrieval + grounding
→ server-allowlisted synthetic fixture만 DeepSeek Flash(30-attempt cap)
→ schema validation + server source metadata
→ SUCCESS/FOLLOWUP may issue fresh 15-minute token; FALLBACK null
→ text-free event; eligible failure only masked text for 30 days
```

- token이나 transcript를 저장하는 DB schema/table은 추가하지 않았다.
- application·web·migration·공식/mock 데이터·prompt 파일은 생성하지 않았다.
- API response conditional 외 DB logical schema 0.2.0-draft는 변경하지 않았다.

### 오류·빈 상태·롤백

- invalid/expired token: 문맥 없는 새 요청, 상세 oracle/transport error 없음.
- cap/429/timeout/invalid output: ACTIVE KB template 또는 정책 FALLBACK 200; 안전 대체 전체 불능만 ADR-0009의 503.
- FALLBACK: token null; 503 envelope에는 token 없음.
- browser reload/tab close: transcript/token 소멸, initial empty state.
- 실제 앱/DB/외부 상태가 없어 이번 rollback은 문서·draft contract rollback만 해당한다.

## 9. 보안·개인정보·접근성·성능 영향

- Privacy: raw 질문·실제 PII·transcript·token을 생성/저장/전송하지 않았다. token claim에 free text/URL/KB body/user ID를 금지하고 current-tab memory only를 계약했다.
- Security: HMAC이 암호화가 아님을 명시하고 최소 32 random-byte server secret, constant-time verify, token 비인증·비권한 원칙과 silent reset을 설계했다. `.env.example`에는 실제 secret 값이 없다.
- Accessibility: UI 코드는 없다. home/chat loading·503 retry·empty office·current-tab reset과 390/430px·keyboard/focus 기준을 계획/TASKS에 추가했다.
- Performance/cost: 실제 outbound 0, 신규 비용 0원. concurrency 1, max 1024, retry 1, attempt cap 30, no top-up으로 잔액을 보호한다. 15분 token은 서버 session storage/load를 만들지 않는다.

DeepSeek 공식 정책·모델 확인 기준일은 2026-07-14이며 구현 시작과 live demo 직전에 다시 확인한다. ADR-0005의 공식 models/pricing, Chat Completion/JSON, cache, rate/user ID, terms 링크를 사용한다.

## 12. AI 내부 구현 세부 — 필요할 때만 보면 되는 내용

- HMAC token 예시는 `v1.payload.signature`; canonical JSON과 standard library `hmac/hashlib/base64/json/time/secrets`를 사용하고 별도 JWT dependency를 두지 않는다.
- 현재 request의 명시적 region이 token claim보다 우선하고, SUCCESS/FOLLOWUP도 필요 없으면 token null을 허용한다.
- DeepSeek direct adapter는 이미 필요한 `httpx`를 사용해 별도 OpenAI/DeepSeek SDK와 숨은 retry를 피한다.
- process restart는 새 run이며 cap reset endpoint는 두지 않는다. health/readiness/startup은 provider를 호출하지 않는다.
- API spec SemVer 2.0.0-draft와 route namespace `/api/v1`은 다른 버전 축이다.
