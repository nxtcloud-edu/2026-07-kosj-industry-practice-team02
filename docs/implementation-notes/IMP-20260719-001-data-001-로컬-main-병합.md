## 5. 설계 결정과 대안

### 선택

`main`을 `aa52c42`에서 feature HEAD `00d9648`로 `git merge --ff-only` 통합하고, 병합된 결과에서 전체 검증을 새로 실행했다.

### 이유

feature가 `main`에서 갈라진 뒤 `main`에 별도 커밋이 없어 merge-base가 정확히 기존 HEAD였다. 불필요한 merge commit 없이 동일한 검토 트리를 기준선으로 만들 수 있었다.

### 고려했지만 선택하지 않은 대안

- push/PR: 사용자가 1번을 선택했고 원격도 없으므로 제외했다.
- 브랜치 보존: 통합 후 중복 작업공간을 남길 필요가 없어 제외했다.
- 강제 reset/squash: 검토된 커밋 이력과 데이터 계보를 훼손할 수 있어 사용하지 않았다.
- PM 승인/official 승격 동시 수행: 독립 인간 검수 게이트를 우회하므로 명시적으로 제외했다.
