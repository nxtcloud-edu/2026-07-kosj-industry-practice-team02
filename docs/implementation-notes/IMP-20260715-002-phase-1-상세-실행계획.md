## 5. 설계 결정과 대안

### 선택

- 한 worktree에서 구현 에이전트 한 명씩 순차 쓰기, 각 task 후 fresh reviewer.
- root는 dependency/Git/install·계약/보안·최종 검증을 직접 통제한다.
- Task 1이 Python 3.12 exact pin을 끝내기 전 API lock 생성을 금지한다.
- `/ready=503`을 Phase 1 성공 조건으로 명시하고, 승인된 contract invariants만 강화한다.

### 이유

- shared lock/manifest 충돌을 피하고, 실패 원인과 rollback commit을 작게 유지한다.
- 사용자 승인 없이 공개 동작이나 production dependency가 확장되는 것을 막는다.

### 고려했지만 선택하지 않은 대안

- 동시 다중 구현 에이전트: lock과 공통 문서 충돌 때문에 제외.
- DB를 먼저 띄워 ready 200 강제: 승인 공식 seed가 없어 거짓 readiness이므로 제외.
- 기존 legacy backend 복사: 현재 계약·개인정보 정책과 불일치하여 제외.
- latest 범위 지정(`^`, `>=`): 재현성이 없어 exact pin과 lock으로 대체.
