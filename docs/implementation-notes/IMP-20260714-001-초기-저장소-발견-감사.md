## 5. 설계 결정과 대안

### 선택

1. 제품 코드·공개 계약·DB/source-of-truth를 수정하지 않고 발견 문서와 필수 메타 문서만 작성했다.
2. 문서 주장을 그대로 수용하지 않고 실제 파일·명령·데이터 count로 재검증했다.
3. 이미 결정된 제품 범위·안전 원칙은 질문하지 않고, 초안 불일치는 “정합화 결함”으로 분류했다.
4. 질문은 구현 전에 인간 결정이 필요한 A 7개만 첫 배치에 포함했다.
5. 결정 로그·ADR·모호성 레지스터·TASKS 상태는 사용자 답변 전이므로 변경하지 않았다.
6. 외부 LLM/DB/배포 연결, dependency 설치, Git init은 하지 않았다.

### 이유

- 사용자 요청과 `AGENTS.md`가 A/Blocker 해소 및 계획 승인 전 대규모 구현을 금지한다.
- contract/DB의 안전 방향은 이미 source-of-truth에서 확정돼 있어 같은 결정을 다시 묻는 것은 불필요하다.
- Git 경계와 공식 데이터·admin 보안·retention은 기본값만으로 실제 구현을 진행하면 복구·개인정보·무단 승인 위험이 크다.

### 고려했지만 선택하지 않은 대안

- legacy FastAPI를 실행해 기능을 이어 붙이기: 10개 분야, P2 API, 오래된 enum·로그·가짜 데이터가 있어 제외.
- 이 폴더에서 즉시 `git init`: 원본 remote/history 존재 여부를 모른 채 상태를 바꾸므로 제외.
- pnpm/uv/PyYAML/tzdata 설치: 새 도구/의존성 승인 전이므로 제외.
- 계약/DB 초안을 즉시 수정: 첫 인터뷰와 실행계획 승인 전 공개 계약·migration 방향을 바꾸므로 제외.
- 현재 출처대장을 ACTIVE seed로 간주: 작성자·검수자·승인 상태가 없어 금지.
- 모든 A/B를 한 번에 질문: 한 번에 최대 7개 규칙 때문에 A 우선, 나머지 B는 다음 배치로 유보.

## 11. 인간이 반드시 알아야 하거나 승인할 내용

1. 현재 폴더는 유효한 Git 저장소가 아니므로 구현 이력·rollback이 보장되지 않는다.
2. 앱은 실제 구현 0이며 7/14 정상 답변 데모 일정과 현재 상태가 맞지 않아 재기준이 필요하다.
3. 공식 ACTIVE KB/기관 데이터가 0건이므로 지금 시민 답변을 만들면 원칙 위반이다.
4. public admin은 인증/RLS가 결정되기 전 노출할 수 없다.
5. retention 30일과 candidate FK 처리 방법은 privacy/schema/migration을 바꾸므로 결정이 필요하다.
6. LLM/DB/배포 공급자·계정·리전·비용·로그 정책은 미확정이다.
7. 개발 runtime/package manager 선택은 새 도구 설치와 전체 재현성에 영향을 준다.
8. 첫 질문 7개에 답한 뒤에도 A blocker가 남으면 제품 구현은 계속 보류한다.
